# 인트라넷 (팀 업무 시스템)

**팀원 접속 주소: https://phb.kr/** (2026-09-15 개통 · 가비아 도메인 phb.kr, 옛 주소 chairman87.github.io/bizhome 은 자동으로 넘어옴)
- 저장소: Supabase 프로젝트 `bizhome` (서울) · 화면 파일: GitHub `chairman87/bizhome`
- 화면 파일을 고친 뒤에는 폴더의 **`올리기.bat`** 을 더블클릭하면(또는 클로드에게 "올려줘") GitHub 에 올라가고 1~2분 뒤 반영됩니다. 이 폴더는 GitHub 저장소와 git 으로 연결되어 있습니다(2026-09-15).

노션 대신 쓰는 우리 팀 업무 시스템입니다. 대문(비즈홈)에서 메뉴를 고르면 각 화면이 열립니다.
파일 몇 개로 동작하며, 내용은 Supabase(무료 클라우드 저장소)에 저장되어 어디서나 접속할 수 있습니다.

## 사용자와 관리자
- 접속하면 이름을 고르고 비밀번호를 넣어 들어갑니다. **처음 비밀번호는 1234** 이고, 1234로 들어오면 새 비밀번호(4자 이상)를 정하는 화면이 먼저 나옵니다.
- 관리자는 팀원 관리에서 모든 비밀번호를 볼 수 있고, 잊은 사람은 **초기화** 로 1234로 되돌립니다. 팀원 추가는 관리자만 합니다(새 팀원도 1234로 시작).
- **처음 등록한 사람이 관리자**가 됩니다. 관리자는 오른쪽 위 이름 → 팀원 관리에서 다른 사람을 관리자로 지정하거나 팀원을 삭제할 수 있습니다.
- 관리자만 할 수 있는 것: 홈 메뉴 편집, 휴가 승인/반려, 팀원별 연차 총 일수 조정, 팀원 삭제.

## 화면
### 비즈홈 (`index.html`)
- 부서별 메뉴 카드. 처음에는 인사(연차/휴가 등록, 멤버 리스트), 업무지원(업무요청/보고) 만 들어 있습니다.
- 관리자는 오른쪽 위 **메뉴 편집**으로 부서·페이지를 추가/이름 변경/아이콘 변경/삭제/순서 변경할 수 있습니다.
- 페이지에 "누르면 열리는 화면"을 지정합니다. 새 화면(html)을 만들면 `index.html` 의 `SCREENS` 목록에 한 줄 추가하면 선택지에 나타납니다.

### 업무요청/보고 (`tasks.html`)
- 흐름: 요청자가 **업무 요청**(담당자·마감일 지정) → 담당자가 **진행 보고**(진행률 + 내용) → 100% 보고하면 `보고완료` → 요청자가 **완료처리** 또는 **보완 요청**
- 상태: 요청 / 진행중 / 보고완료 / 완료 / 보류
- 탭: 받은 업무(내가 담당자) / 요청한 업무(내가 요청자) / 전체(요약 칸 포함) / 보관함(완료) / 담당자별 / 상황판(단계별 카드) / 달력
- 빨간 숫자: 내 차례(새 요청·보고 확인·보완 답변)인데 **아직 열어 보지 않은** 업무 수. 업무를 눌러 열면 사라지고, 그 뒤 남이 보고·댓글을 남기면 다시 생깁니다. 본 시각은 `tasks.seen` 칸에 저장(`sql-tasks-seen.sql` 을 한 번 실행). 칸이 없으면 그 브라우저에서만 기억합니다

### 연차/휴가 등록 (`leave.html`)
- 흐름: 팀원이 **휴가 신청**(종류·기간·사유) → 관리자가 **승인** 또는 **반려**. 승인 전에는 신청자가 취소 가능
- 종류: 연차 / 오전 반차 / 오후 반차 (연차에서 차감) · 병가 / 경조사 / 기타 (차감 안 함). 일수는 토·일을 뺀 평일 수
- 탭: 내 신청(남은 연차 요약) / 전체(관리자 승인 대기 표시) / 달력 / 팀원별 현황(연차 총 일수 조정)

### 상표관리 (`trademarks.html`, 2026-10-08)
- 메뉴: 인사/재무/법무 > 상표관리. 두 회사(식이해법연구소 · (주)피에이치뷰티)의 상표를 한 줄씩(나라별로 따로) 둡니다
- 상태: 출원 → 공고 → 등록 / 거절 / 포기·소멸. 우선심사 표시, 상품류, 출원·등록번호와 날짜, 존속기간 만료일(등록일+10년 자동), 대리인, 비용 내역, 진행 이력, 다음 할 일·기한
- 파일: 등록증 · 등록원부 · 청구서 · 통상사용권허가서 등을 줄마다 첨부(보관함 `files/trademarks/`). 줄을 누르면 보기, 수정에서 파일 추가
- 탭: 전체 / 회사별 / 할 일·기한(90일 안 기한은 주황, 지난 기한은 빨강). 표는 `sql-trademarks.sql` 을 한 번 실행해 만듭니다
- 원본 서류는 나스 `\\192.168.0.10\경영지원\★ 법무\★ 상표` 에도 있습니다(2026-10-08 기준 레모너리·서리맥스·클레올로지·마드리드 출원 서류)

### 자동작업 (`routines.html`, 2026-10-28)
- lemon803 PC 에서 도는 자동작업(윈도우 작업 스케줄러·Claude 앱 예약작업)의 현황·결과·수정요청. 표: `sql-routines.sql` (routines / routine_runs / routine_requests)
- 탭: 작업 현황(종류별 표, 마지막 실행·결과·보고 내용, "늦음" 표시) / 대화 / 수정요청 / 실행 기록
- 대화(2026-10-28): 대상을 하나 고르고 클로드와 글로 주고받으며 고침("지금 어떻게 돼 있어?"도 됨). lemon803 의 chat_worker.py 가 30초~2분 안에 답. 관리자가 고치라고 한 것은 즉시 반영되고(지금 Claude 와 대화하듯), 직원 대화는 복사본에 쌓였다가 **반영 요청** → 관리자 승인 뒤 적용. 작업 현황의 줄을 눌러도 바로 그 작업과의 대화가 열림. 표: `sql-routines-chat.sql` (routine_chats / routine_chat_messages)
- 수정요청 흐름: 요청 → lemon803 의 클로드가 고침(10분 안에) → 검토대기(관리자가 "바꾼 내용"을 보고 승인/반려) → 반영완료. 인트라넷은 승인 1~2분 뒤 phb.kr 반영. 승인 전에는 아무것도 안 바뀜
- 관리자만 보기(🔒) 작업은 직원에게 목록·기록·요청 어디에도 안 보임. 관리자는 줄을 열어 "설정"에서 담당자·관리자만 보기·설명을 고침
- **대화·수정요청 잠금(2026-11-19)**: 예전에는 대화·메시지·수정요청 표가 공개키로 쓰여서, 밖에서 관리자 이름을 적은 글이나 '승인'된 요청을 넣으면 lemon803 의 클로드가 그대로 반영했습니다. 지금은 세 표가 공개키로는 **읽기만** 되고, 쓰기는 전부 서버 함수 `rt_*` 가 합니다(`sql-routines-lock-1.sql` 함수 · `sql-routines-lock-2.sql` 잠그기).
  - 화면은 `rt('rt_chat_send' …)` 처럼 로그인 출입증(`bzToken()`)으로 부릅니다: `rt_chat_send`(글 보내기·대화 만들기) · `rt_chat_apply`(반영: 관리자=바로 승인, 직원=검토대기) · `rt_chat_close` · `rt_chat_delete`(관리자) · `rt_req_new` · `rt_req_remove` · `rt_req_review`(승인/반려, 관리자만) · `rt_req_comment`. 글쓴이·승인한 사람(이름과 번호 `author_id`·`requester_id`·`reviewer_id`)은 서버가 적습니다.
  - 이 세 표에는 `saveRow`·`removeRow`·`insert` 를 쓰지 않습니다(막혀 있어 "저장 실패"가 뜸). 읽기와 실시간 갱신은 예전 그대로입니다.
  - lemon803 의 처리기는 PC 전용 열쇠로 `rt_pc_*` 함수를 부릅니다. 작업 목록·실행 기록(routines · routine_runs)은 예전처럼 공개키로 읽고 쓰는 표입니다(처리기는 고칠 폴더를 이 표가 아니라 routines.json 에서 읽음).
- lemon803 쪽 프로그램(결과 보고 report.py, 처리기 process_requests.py, 설치)은 `클로드코드\ROUTINE-BOARD\README.md`

## 처음 설정하는 순서 (사용자가 직접)
### 1. Supabase 저장소 만들기
1. https://supabase.com 에서 무료 회원가입 후 **New project** (이름: bizhome, 지역: Northeast Asia (Seoul) 추천)
2. 왼쪽 메뉴 **SQL Editor** → **New query** → `supabase-setup.sql` 내용을 전부 붙여넣고 **Run**
3. 왼쪽 메뉴 **Project Settings → API** 에서 두 값을 복사
   - **Project URL** (예: `https://abcdefgh.supabase.co`)
   - **anon public** 키 (긴 글자)
4. `common.js` 맨 위 `CONFIG` 부분에 두 값을 넣습니다
   ```js
   const CONFIG = {
     SUPABASE_URL: "https://abcdefgh.supabase.co",
     SUPABASE_KEY: "eyJ...",
   };
   ```
   (이 키는 "공개용" 키라서 파일에 넣어도 됩니다. 단, 링크를 아는 사람은 누구나 내용을 볼 수 있으니 팀 안에서만 공유하세요.)

### 2. 인터넷에 올리기 (GitHub Pages, 무료)
1. https://github.com 에서 회원가입
2. **New repository** → 이름 `bizhome`, **Public** → Create
3. **Add file → Upload files** 로 `index.html`, `tasks.html`, `leave.html`, `common.js`, `common.css` 를 올리고 Commit
4. 저장소의 **Settings → Pages** → Branch 를 `main` 으로 고르고 Save
5. 1~2분 뒤 `https://<깃허브아이디>.github.io/bizhome/` 주소로 접속 가능. 이 주소를 팀원에게 공유

이후 파일을 고치면 3번(업로드)만 다시 하면 됩니다.

## 인증문자 (authsms.html, 2026-11-19)
- 사무실 아이폰 2대(식이해법 · 피에이치뷰티 정산/세금용)에 오는 인증 문자를 인트라넷에서 봅니다. 핸드폰을 찾으러 가지 않아도 됩니다.
- 아이폰의 단축어 자동화가 '인증'이 든 문자를 `as_in()` 으로 보내고, 서버는 **'인증' + 숫자가 있는 문자만** 받습니다. 24시간 지나면 지웁니다.

## 로그인 잠그기 (2026-11-19)
- **왜**: 팀원 표(`members`)의 비밀번호 칸이 공개키만 있으면 밖에서 그대로 읽혔고, 잠긴 화면(채용·인증문자·카톡 주문·메모장)의 자물쇠가 그 비밀번호였습니다.
- **지금**: 비밀번호는 암호화되어 잠긴 표(`member_secrets`)에 있고, 맞는지는 서버(`think_login`)만 확인해 출입증을 줍니다. 5번 틀리면 10분 잠깁니다. 관리자도 비밀번호를 볼 수 없고 **초기화(1234)** 만 합니다.
- 로그인하면 이 기기에 출입증(`think_token_<사람id>`)이 남고, 잠긴 화면과 팀원 관리가 그 출입증으로 서버 함수를 부릅니다. 출입증이 없거나 거절되면 로그인 화면이 다시 뜹니다(`common.js` 의 `bzToken` · `bzExpired`).
- 팀원 추가·삭제·직급·관리자 지정·운영진 지정·입사일은 서버 함수(`bz_member_save` · `bz_member_delete`)가 관리자인지 확인하고 고칩니다. 공개키로는 팀원 표를 읽기만 합니다. 화면에서는 예전처럼 `saveRow('members', …)` 를 쓰면 됩니다(common.js 가 알아서 서버 함수로 보냄).
- 파일: `sql-login-1.sql`(준비: 암호화 복사 · 서버 함수) → 새 화면 올리기 → `sql-login-2.sql`(비밀번호 칸 삭제 · 팀원 표 잠금 · 예전 출입증 삭제).
- **아직 열려 있는 것**: 업무·결재·서류 등 일반 표는 여전히 공개키로 읽고 쓸 수 있습니다(로그인 화면은 가림막). 보안이 필요한 표만 골라 "잠긴 표 + 서버 함수"로 옮깁니다(2026-11-19 사장님 방침: 전체를 한꺼번에 바꾸지 않고 필요한 곳만).
